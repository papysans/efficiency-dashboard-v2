# 新算法个人提效结果

## 口径

本次使用当前分支新算法输出，不使用 main 老算法。

过滤规则：

- 只看已合并工作项
- 只看边界高/中置信工作项
- 排除异常值
- 排除实际耗时或基线耗时为 0 的工作项

注意：如果严格排除 `confidence_level=low`，这批数据剩余 0 条，无法出个人结果。因此这里采用“排除低边界置信 + 排除异常值”的可汇报口径。

完整明细：

- `docs/data/efficiency_v2_person_efficiency.csv`

## 总体结果

| 指标 | 值 |
|---|---:|
| 覆盖人数 | 24 |
| 覆盖工作项 | 39 |
| 实际日历耗时 | 375851.93 分钟 |
| 基线日历耗时 | 400924.26 分钟 |
| 日历口径整体提效 | 6.67% |
| 实际工作量 | 154389.45 分钟 |
| 基线工作量 | 140323.49 分钟 |
| 工作量口径整体提效 | -9.11% |

解释：

- 日历口径：AI 参与后，从工作开始到完成的整体周期缩短了 6.67%。
- 工作量口径：按实际投入分钟看，当前样本整体没有体现节省，反而高 9.11%。
- 因此早会更稳妥的说法是：新算法已经能算到个人提效，但当前可用样本下，日历周期有一定缩短，工作量节省还没有体现出来。

## 早会表述

可以这样说：

> 我们用新算法重新跑了一版个人提效，排除了低边界置信和异常工作项后，剩下 24 个人、39 个工作项。整体看，按交付周期口径有 6.67% 的提效；但按实际工作量口径是 -9.11%，说明当前样本里 AI 对交付周期有缩短迹象，但对实际投入工时的节省还不稳定。个人层面已经能算出结果，但多数人覆盖的工作项数量偏少，暂时不适合做强排名。

# 页面说明书 · 设置区（定价 / 数据源 / 同步任务 / 系统配置）

> 路由 `/kanban/settings/{pricing,datasources,sync,config}`
> 组件 `frontend-react/src/pages/settings/*`

---

## 0. 这四页是什么（共同前提）

设置区四页是**外部 chat-indicator-statistics 服务的管理后台**——它们经看板后端的反向代理（`/api/v2/chat/*`）配置那个服务的价格表、数据源、同步任务、系统参数。

> ⚠️ **重要澄清**：
> 1. 这四页配的是**外部 chat 服务**，**与看板的提效指标（commit/task/need）算法无关**。CRUD 落库在外部服务，看板只透传。
> 2. **"人天单价"不在这里**。驱动总览"净节省¥"的 `cost_per_person_day`（默认 2000）只在**看板后端 yaml 配置，没有前端设置页**。本设置区的 system_currency/汇率只影响外部 chat 服务的 LLM token 成本。
> 3. **权限**：当前系统**无独立角色门禁**（后端 v2 路由无 auth 中间件，auth shim 把访问者当 admin）。访问控制依赖内网网络隔离 + 上游 chat 服务可选的 Basic Auth。说明书不应写"需 platform_admin"。

---

## 1. 模型价格（Pricing）
配置各 LLM 模型的计费单价，供 chat 服务算 token 成本。
- 字段：模型名 / 计价模式（token·request·hybrid）/ 输入·输出·缓存单价（**界面按"每 1M tokens"录入，提交时折算为 per-token**）/ 请求单价 / 原始货币+汇率（非系统币种需填汇率，换算在 chat 后端做）/ 生效·失效日期 / 备注。
- 操作：新增/编辑/删除/详情。

## 2. 数据源（Datasources）
配置 chat 服务从哪里抽取原始指标——PostgreSQL 或 Elasticsearch 源库。
- 字段：名称 / 类型 / 启用 / PG（host/port/database/schema/table/账号/ssl_mode）或 ES（hosts/index/账号/scroll/verify_certs）/ 备注。
- 操作：新增/编辑/删除/**逐行连接测试**。
- ⚠️ **连接测试失败也是 HTTP 200**，必须看返回体的 `success/message`，不能只看请求是否成功。

## 3. 同步任务（SyncTasks）
**手动发起一次"补数据"ETL**（选数据源 + 时间段）+ 任务列表。
- 提交项：数据源（仅列启用的）/ 开始·结束时间 / **强制覆盖**（先删该段汇总再重算）。
- 任务列表：任务 ID / 状态（pending/running/completed/failed/retrying）/ 进度条 / 处理·写入行数 / 错误；有进行中任务时每 5s 自动轮询。可重试 failed、停止 active。
- ⚠️ **此页同步的是外部 chat 服务的 ETL，不是看板 kbcli 的 import/efficiency-v2**。客户若以为在此看 kbcli 任务状态，是误解（kbcli 任务是看板自己的 cron，不在此页）。

## 4. 系统配置（SystemConfig）
chat 服务的全局 KV 参数。
- 项：每日自动 ETL 开关 / cron 表达式（默认每天凌晨 2 点）/ 定时 ETL 绑定数据源（留空则不执行）/ 系统币种（CNY 等）/ 默认汇率（7.2420）。
- 操作：保存（逐键 upsert）。

---

## 5. 边界与常见质疑应答

**Q：这里配的价格/币种会影响看板的"净节省¥"吗？**
不会。看板"净节省"用的是后端 yaml 的 `cost_per_person_day`（人天单价，默认 2000），与本设置区（外部 chat 服务的 token 价格/币种）是两套独立概念。

**Q：同步任务能触发看板重新算提效吗？**
不能。此页是外部 chat 服务的指标 ETL。看板的数据导入与提效重算（kbcli import / efficiency-v2）是另一条链路（看板 cron），不在此页。

**Q：谁能改这些设置？**
当前系统无独立角色校验，靠内网隔离 + 上游 chat 服务可选 Basic Auth 控制。部署在内网时，能访问看板即可操作。

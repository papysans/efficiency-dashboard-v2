# 页面说明书 · 提交列表（CommitList）

> 路由 `/kanban/commit-v2`
> 组件 `frontend-react/src/pages/commits/CommitList.tsx`
> 数据接口 `GET /api/v2/commits`（`endpoints.ts:161`）

---

## 0. 这个页面是什么

按提交查代码产出明细：代码量、耗时、Token、费用。

> **本页刻意不展示提效比**（单 commit 大多算不出，提效看需求/用户/组织层；提效比保留在《提交详情》）。工时为 V1 古法口径（→白皮书§12）。

---

## 1. 列速查表（11 列）

Commit ID（截 8，可点）/ 时间 / 组织 / 用户（真名，可点）/ 说明 / 仓库（可点）/ 代码量（原始 diff）/ **实际耗时（manual 优先）** / **传统耗时预估（manual 优先，古法）** / Tokens / 费用。空值显 `-`。

> **耗时派生**：列表里若某 commit 实际/古法工时缺失（≤0），后端用 Need 工时平摊 + 提交间隔法兜底补值（→§12.5）。**所以耗时列可能是派生估算值，非原始记录**，前端不区分标记。

---

## 2. 筛选 / 排序 / 分页

- **日期**：服务端筛选。**用户名/组织**：客户端兜底过滤（只过滤当前页）。
- **排序（混合）**：服务端列（时间/代码量/费用）+ 客户端列（实际耗时/传统耗时预估，manual 优先）。
- **分页**：服务端，pageSize 默认 250（250/500/1000）。

---

## 3. 边界与常见质疑应答

**Q：耗时是怎么算的？**
优先用 commit 的实际记录工时；缺失时由后端派生（所属 Need 工时按 commit 数平摊，再不行用同用户相邻提交间隔估算，→§12.5）。被追问时可指向白皮书 §12.5。

**Q：代码量和需求页的"净代码行"对不上？**
本页"代码量"是 commit 原始 `diff_lines`；需求页"净代码行"是治理后有效行（软上限/降权/排除后）。口径不同（→§1 治理）。

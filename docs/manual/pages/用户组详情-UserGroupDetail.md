# 页面说明书 · 用户组详情（UserGroupDetail）

> 路由 `/kanban/user/group/:groupId`
> 组件 `frontend-react/src/pages/users/UserGroupDetail.tsx`
> 数据接口 `GET /api/v2/user-groups/{id}`（`endpoints.ts:283`），删除 `DELETE /v2/user-groups/{id}`

---

## 0. 这个页面是什么

一个"虚拟组"（手动圈定的一批用户）的汇总：① 6 张卡 → ② 成员明细表 → 删除操作。

> ⚠️ **本页是 V1 古法口径（百分比，PercentPill，不再 ×100）**，与《用户列表/详情》的 V2 融合口径（小数）**完全是两套，不可横向比较**（→《01-算法白皮书》§12）。同一用户在用户详情看到的"日历提效"（小数口径）和在本页看到的"Task/Commit 提效比"（百分比口径）数值不可换算。

---

## 1. 字段速查表

### 6 张汇总卡（`UserGroupDetail.tsx:103-110`）
| 显示 | 含义 | 口径 | 空态 |
|---|---|---|---|
| 成员数 | 组内用户数 | 计数 | 0 |
| 总 Task 数 / 总 Commit 数 | 各成员累加 | 🔢 | 0 |
| 加权 Task 提效比 | `(合计古法−合计实际)/合计实际×100` | **百分比口径**（→§12.2） | 缺数→`0.0%` |
| 加权 Commit 提效比 | 同上（commit 工时） | 百分比口径 | 缺数→`0.0%` |
| 总费用 | 各成员累加 | ¥ | null→`-` |

> "加权"= 先对全组古法分钟、实际分钟分别求和，再算一次比率（工时加权，非比率平均）。

### 成员明细表（7 列）
用户名（可点）/ 活跃天数 / Task 数 / Commit 数 / Task 提效比 / Commit 提效比 / 费用。各成员数据来自 `tasks`+`commits` 按天聚合（V1 链路）。

---

## 2. 筛选 / 排序 / 分页

无客户端排序/分页（成员按组内 user_ids 原序）。**有日期选择器**，改日期即重查。

---

## 3. 边界与常见质疑应答

**Q：某成员提效比显示 `0.0%`，是真的零提效吗？**
不一定。本页比率字段恒有值，**缺数据时显 `0.0%` 而非 `-`**（古法工时为 0 时比率算作 0）。`0.0%` 可能代表该成员在所选区间内 tasks/commits 无数据，需结合 Task/Commit 数判断。

**Q：用户组的提效比和用户详情的提效比为什么差很多？**
两套口径：用户组是 V1 古法百分比（基于 tasks/commits 工时），用户详情是 V2 融合小数（基于需求边界）。数据源、公式、过滤都不同，**不可比**（→§12）。汇报时务必标明用的是哪套。

**Q：怎么新建/查看用户组列表？**
当前前端只支持按已知组 ID 直链查看与删除，**没有创建入口、没有用户组列表页**。该功能为半成品状态。

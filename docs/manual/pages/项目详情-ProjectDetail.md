# 页面说明书 · 项目详情（ProjectDetail）

> 路由 `/kanban/project/:projectId`
> 组件 `frontend-react/src/pages/projects/ProjectDetail.tsx`
> 数据接口 `GET /api/v2/projects/{id}`（`endpoints.ts:228`）

---

## 0. 这个页面是什么

单个项目（手动圈定的 Repo/Task 虚拟聚合）的明细 + 管理操作：① 基础信息 → ② 度量信息 → ③ 用户视角 → ④ Repos → ⑤ Tasks → ⑥ Commits。

> ⚠️ **项目为 V1 古法口径**，与需求/用户/部门的 V2 融合口径不可比（→白皮书§12）。本页提效比是"倍数"展示（见 §3）。

---

## 1. 字段速查表

### ② 度量信息
传统开发预估 / 实际处理耗时 / 项目周期（均工时，含 reason 悬浮）/ 总 Tokens / 总费用 / 生成代码量 / 实际耗时(人天) / 实际人天代码量 / 传统开发人天代码量 / **开发提效比** / **端到端提效比**。
- **开发提效比** = `传统开发预估人天 ÷ 实际耗时人天`（倍数，如 3 倍显示 300%）。
- **端到端提效比** = `传统开发预估人天 ÷ 项目周期人天`。

### ③ 用户视角（前端按 user_id 聚合）
用户 / Task 数 / Commit 数 / 代码行 / Task 传统预估·实际耗时·提效比 / Commit 传统预估·实际耗时·提效比 / 费用。提效比为"倍数"百分比（`古法/实际×100`）。

### ④ Repos / ⑤ Tasks / ⑥ Commits
- Repos：仓库地址（可点）/ 分支 / 起止时间 / 白名单·排除 commits 数 / 操作（编辑·删除）。
- Tasks：Task ID（可点）/ 用户 / 开始时间 / 传统预估 / 实际耗时 / **AI 代码权重 silica** / 费用 / 操作。
- Commits：Commit ID（可点）/ 用户 / 时间 / 说明 / 代码行 / 传统预估 / 实际耗时 / **AI 代码占比（commit 级 silica，直接百分比）**。

---

## 2. 管理操作

编辑（改名/描述）/ 删除 / 加 Task / 移 Task / 改 Task AI 代码权重 / 加 Repo（含时间窗+黑白名单）/ 移 Repo。所有写操作后后端重算项目聚合并刷新。
- 加 Repo 到 Project 的入口在《仓库详情》会先做**冲突检测**；本页的加 Repo 直接添加。
- **注**：项目详情的"人工调整"功能已按口径下线决策移除（任务/提交详情仍保留）。

---

## 3. 边界与常见质疑应答

**Q：项目详情的提效比和项目列表对不上？**
口径不同：
- **项目列表**用"提升百分比"`(古法−实际)/实际×100`（3 倍 → 200%）。
- **项目详情**的"开发提效比/端到端提效比"用"倍数"`古法/实际`（3 倍 → 300%）。
同一项目，列表和详情可能给出不同数值。汇报时请统一选用其一并说明口径。

**Q：commit 行的"AI 代码占比"是什么？**
是 commit 级 `silica`（该提交匹配 AI 产出的行占比，直接当百分比，阈值 80/50 着色），与需求级 `ai_code_ratio` 不同口径（→§2.10）。

**Q：项目工时是真实记录吗？**
古法/实际工时来自命中 commits 的工时累加，缺失时由 Need 平摊 + 提交间隔法派生（→§12.5），是真实与估算的混合。

**Q：编辑项目时要注意什么？**
"编辑"只改名/描述，但后端会整体覆盖 repos/task 配置——前端已自动回传原值以防清空。加/删 Repo 用数组下标，操作后会自动重载。

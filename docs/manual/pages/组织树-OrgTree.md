# 页面说明书 · 组织树（OrgTree）

> 路由 `/kanban/org-tree-v2`
> 组件 `frontend-react/src/pages/orgs/OrgTree.tsx` + `DeptMembersPanel.tsx`
> 数据接口 `GET /api/v2/dept-tree`（部门树）+ `/v2/dept-tree/members`（部门成员）

---

## 0. 这个页面是什么

左侧是**部门树**（来自外部 dept-sync 权威部门数据），右侧是选中部门的**成员花名册 + 看板提效指标**。

> 成员的提效指标走 **V2 融合口径（小数，RatioPill ×100）**（→白皮书§6.2），与需求/用户页同源。部门树本身只读、与日期无关。

---

## 1. 字段速查表

### 左树
部门名 + 子部门数徽标 + 展开箭头。后端把 dept-sync 返回的森林（含脏数据孤儿部门）重建成**单根树**，孤儿/断链部门被排除（`dept_tree_handler.go:171-252`）。

### 右栏 · 部门汇总卡
成员数 / 合并需求 / 实际周期 / 日历提效 / 人力提效 / AI 代码占比 / Commit·代码行 / 费用。口径同《用户列表》（合计口径）。
> 提示：成员数旁的 hint 显示"其中 N 人有看板数据"——dept-sync 成员里部分人无看板活动。

### 右栏 · 成员表
成员（真名，可点进用户详情）/ 工号 / 职级（来自 dept-sync）/ 合并需求 / 实际周期 / 日历提效 / 人力提效 / AI 代码占比 / Commit·代码行。无看板数据的成员各指标显 `—`，仍列出（挂"无活动"浅标）。

> **看板指标如何挂到部门成员**：按 `universal_id`（= dept-sync 工号体系的 UUID）左连看板 `user_id`，内网实测约 98.6% 命中（`dept_tree_handler.go:309-310`）。

---

## 2. 筛选 / 排序 / 分页

- **无分页、无客户端排序输入**：成员顺序由后端定（有看板数据者上提，活跃组内按合并需求→提交→实际日历降序）。
- **日期**：右栏指标随 URL 日期（默认近 90 天）；树与日期无关。

---

## 3. 边界与常见质疑应答

**Q：点一个部门，成员是只看直属，还是含下级部门？**
**含整棵子树的全部成员**（后端按 `include_children=true` 取，`dept_tree_handler.go:255-259`）。点公司根会返回全员（可能上万人，靠长超时兜住）。

**Q：某成员各项指标都是 `—`？**
该成员在 dept-sync 有，但在看板没有提交/会话活动（或 universal_id 未与看板 user_id 对上）。属数据覆盖，不是 bug。

**Q：部门维度提效比是哪套口径？**
V2 融合小数口径，与用户/需求页一致、可比；**与仓库/项目/用户组（V1 古法百分比）不可比**（→§12）。

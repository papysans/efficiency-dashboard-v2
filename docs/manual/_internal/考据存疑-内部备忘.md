## 【重大】两套提效比口径体系并存（影响白皮书结构 + 全部仓库/项目/用户组页）

考据 Users/Repos/OrgProj 三组发现：系统并存两套**互不可比**的提效比口径——

- **V2 融合口径（小数，RatioPill ×100 显示）**：`(baseline−actual)/actual`，efficiency-v2 needs 管线。用于：需求各页、用户列表 UserList、用户详情 UserDetail、总览 Overview、部门成员面板 DeptMembersPanel。白皮书 §6.2 已写。
- **V1 古法口径（百分比，PercentPill 不再 ×100）**：`CalcEfficiencyRatio(ancient,real)=(ancient−real)/real×100`（`core/utils/calc.go:9-15`），数据来自 commits/tasks 表的 `commit_ancient_minutes/commit_real_minutes`（缺失时 `deriveCommitWorkMinutesBatch` 实时派生：Need 工时平摊 + 提交间隔法兜底 `commitGapMaxMinutes=120`/`commitFirstSessionMinutes=30`，`db.go:725-838`）。用于：**用户组 UserGroupDetail、仓库列表 RepoList、仓库详情 RepoDetail（提效比+工时列）、项目列表 ProjectList、项目详情 ProjectDetail**，以及 `/v2/orgs/detail`（V1 org1~9 旧维度，前端无页面消费）。

**处理决定**：白皮书必须新增一节《V1 古法提效比口径》对外说明（否则仓库/项目/用户组页字段无据），并明确"两套口径不可横向比较"。需另考据 V1 古法 commit/task 工时的**写侧生成**口径（白皮书 §5.1 只覆盖 Need 级古法基线，未覆盖 commit 级）。

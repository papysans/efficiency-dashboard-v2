# 00 · 总纲与术语表

> 本篇是说明书的"地基"：先讲系统做什么、数据怎么流动，再给一份核心名词字典，统一全书口径。读其余各册前先读本篇。

---

## 1. 系统是什么

这是一套 **AI Coding 提效度量看板**。它采集开发者使用 AI 编程工具（会话）与代码提交，自动识别"需求边界"，估算"不用 AI 要花多久"，与实际投入对比，得出**提效比**，并按需求/用户/组织/仓库/项目等多维度展示。

**技术栈**：Go(Gin) 后端 + PostgreSQL + React 前端；数据采集与计算由 `kbcli` 命令行完成。

---

## 2. 数据流（一条数据从采集到看板）

```
原始采集（会话 / 提交 / 任务）
   → ① 数据治理 governance（脱敏 / 排除 bot·纯文档 / 巨型提交软上限 / 重放去重 / merge 归零）
   → ② 需求边界与 Episode 分桶（聚合成 Need，定边界来源/置信、按长搁置切段）
   → ③ 工时口径（日历周期 & 人力活跃）
   → ④ 阶段划分（思考/执行/验证/其他）
   → ⑤ 三路工时基线（古法 / kNN / LLM）
   → ⑥ 基线融合（→两套提效比）
   → ⑦ 置信分档 & 异常隔离
   → ⑨ 资格判定（是否计入统计）
   → 前端各页面展示
```

每一步的真实公式与代码出处见《01-算法白皮书》。

## 3. 核心名词字典

### 实体
| 名词 | 含义 |
|---|---|
| **Need（需求）** | 一段被识别出边界的连续开发工作（通常对应一个特性分支/PR/Issue），是提效统计的主单元。 |
| **Session（会话）** | 一次 AI 编程会话。 |
| **Commit（提交）** | 一次代码提交。 |
| **Task（任务）** | 单次 AI 编程任务（≈一段会话），AI 使用明细的最小单元；不单独算提效。 |
| **WorkDir（工作目录）** | 按工作目录聚合的提交视图。 |
| **Episode（分桶段）** | 同一边界内按 >3 天长搁置切分出的连续开发段。 |

### 口径
| 名词 | 含义 |
|---|---|
| **日历口径** | 自然时间跨度（开发开始→结束，扣除 >3 天长搁置）。回答"花了多少天"。 |
| **人力/活跃口径** | 实际活跃投入的人·分钟（多会话/多人去重）+ 未覆盖补估。回答"花了多少人力"。 |
| **估算口径** | 采集未覆盖部分由算法补估（思考/执行为粗略估算，验证当前采集未覆盖）。 |
| **V2 融合口径（小数）** | 需求级提效比，`(传统−实际)/实际`，小数（0.25→25%），前端 RatioPill ×100 显示。用于需求/用户/总览/部门。 |
| **V1 古法口径（百分比）** | commit/task 级提效比，`(古法−实际)/实际×100`，已是百分比（300→300%），前端 PercentPill 不再 ×100。用于仓库/项目/用户组/提交。 |
| **⚠️ 两套口径不可横向比较** | V2 的 3.0（=300%）和 V1 的 300（=300%）不能放一起比。每页属于哪套口径见《01-算法白皮书》§12 对照表。 |

### 算法
| 名词 | 含义 |
|---|---|
| **古法基线（algo）** | 按代码量+会话信号的工程经验公式估"不用 AI 要多久"。 |
| **kNN 相似锚点** | 用历史相似需求的真实工时估时（逆距离加权）。 |
| **LLM 估算** | 大模型读需求摘要后估时。 |
| **融合（fusion）** | 三路基线按权重融合成"传统人力预估"。 |
| **Outlier 异常隔离** | 极端提效比打标签并移出统计池，**只隔离不改数**。 |
| **资格判定（coverage_eligible）** | 决定该需求是否计入提效统计（merged + 边界可信 + 日历>0 + 有会话）。 |

### 数据/治理
| 名词 | 含义 |
|---|---|
| **silica** | commit/task 级"AI 代码证据"——该提交匹配 AI 产出的行占比。与需求级 `ai_code_ratio` 不同口径。 |
| **ai_code_ratio** | 需求级"AI 代码占比"= AI 覆盖行 / 净代码行。 |
| **数据治理 governance** | 计算前的写侧清洗：脱敏、排除、软上限、降权、去重、归零。只打标记不删数据。 |
| **有效行数 GetEffectiveDiffLines** | 治理后的统一行数入口（被排除→0），LOC/AI占比/古法基线全口径共用。 |
| **manual 优先** | 工时字段若有人工调整值则优先于算法值（任务/提交详情可设）。 |

# 03 · 数据质量与常见质疑应答（汇报防弹衣）

> 本篇把全系统"看起来像 bug、实为数据限制或设计选择"的点汇总成统一应答稿。汇报时被追问，可直接引用。每条都给"现象 → 解释 → 代码/章节依据"。各页面文档的"边界与常见质疑应答"是本篇的局部展开。

---

## A. 提效比相关

**Q1：某个提效比是夸张的大数（如 +1500%）？**
该需求触发了**异常隔离但指标不裁剪**。当日历提效 >10 或人力比 >5 时，系统打"日历异常/工作量异常"标签并把它移出统计池，但卡片仍显示真实原值（白皮书 §8）。极端值通常源于一侧数据不完整（活跃工时偏小或日历偏短）。看到异常标签即说明该样本已被隔离、不污染总体。

**Q2：同一个东西，仓库页是 300%、需求页是 3.0，差了 100 倍？**
不是错误，是**两套口径**。需求/用户/总览/部门用 V2 融合小数口径（3.0 = 300%），仓库/项目/用户组/提交用 V1 古法百分比口径（300 = 300%）。**两套不可横向比较**（白皮书 §12）。汇报时务必先说明该页属于哪套口径。

**Q3：项目列表和项目详情的提效比不一样？**
项目列表用"提升百分比"`(古法−实际)/实际×100`（3 倍→200%），项目详情的"开发提效比"用"倍数"`古法人天/实际人天`（3 倍→300%）。同一项目两页口径不同，选用其一并说明即可。

**Q4：提效比显示 `0.0%` 或 `-`？**
- `0.0%`（用户组/部分 V1 页）：该口径在分母≤0 时返回 0，**"无法计算"和"真持平"都显示 0.0%**，需结合工时/数量判断。
- `-`：通常代表无数据或不可计算。

## B. 资格与"未计入"

**Q5：这个需求明明已经 merged，为什么显示"未计入"？**
资格判定初判通过后还有两道否决：① 实际周期 ≤0（有交付物但日历为 0，常见于单提交/零跨度）；② 该需求下没有任何 AI 会话（commit-only）。命中任一即改回"未计入"（白皮书 §9）。这是为了不让缺时间侧数据的样本虚增提效。

**Q6：可计入需求占比偏低？**
主因是**数据采集完整度**，不是真实提效低。缺时间侧（无会话）或交付侧（零日历）的需求被排除统计。资格率反映上报完整度（白皮书 §9、§11）。治理不能补缺失的采集数据。

---

## C. 工时与阶段

**Q7：验证阶段（思考/执行/验证里的验证）几乎全是空？**
当前数据采集不记录"命令执行"类事件（go test / npm build 等），验证阶段无数据来源，故普遍为 0（前端显 `—`）。这是采集覆盖的结构性缺失，思考/执行为粗略估算口径、有兜底所以总有值（白皮书 §4.2）。

**Q8：仓库/提交页的工时是真实记录吗？**
是"真实记录 + 派生估算"的混合。当某 commit 工时缺失时，后端用所属 Need 工时按提交数平摊、再不行用同用户相邻提交间隔估算（白皮书 §12.5）。被追问可指向 §12.5。

**Q9："有 commit 没提效"？**
该需求可能因日历为 0 或 commit-only 被资格否决（Q5），或因提效比极端被异常隔离（Q1）。两种情况下需求有提交但不出现在提效统计里。

## D. 代码量与 AI 占比

**Q10：需求页"净代码行"比提交的 diff 之和少很多？**
口径不同。提交列表的"代码量"是**原始 diff**；需求页"净代码行"是**治理后有效行**——治理对超大 build/merge/生成文件做软上限、对纯注释/纯文档降权或排除（白皮书 §1）。差额即被治理挤掉的"水分"。

**Q11：commit 的"AI 代码占比"和需求页的"AI 代码占比"对不上？**
两者同名不同口径：commit 级是 `silica`（该提交匹配 AI 产出的行占比），需求级是 `ai_code_ratio`（需求净行里 AI 覆盖占比）。汇报时应区分措辞（白皮书 §2.10）。

**Q12：AI 占比有时显 `0.0%`、有时显 `-`？**
列表对 0 值显 `0.0%`，详情对 0 值显 `-`，底层是同一指标。commit 级 silica 默认 0，`0.0%` 既可能是"确无匹配"也可能是"未计算指纹"。

## E. 方法论可信度（被问"这套数准不准"）

**本系统是估算性度量**，用于反映 AI 编程的提效趋势与分布，不宜当作精确工时账。三个口径边界要主动说明：
1. 三路基线（古法/kNN/LLM）是估算、互为印证，融合降低单一方法偏差，但不等于精确测量（白皮书 §5、§11）。
2. AI 覆盖按时间窗判定（提交时间是否落入会话窗口），不按文件内容比对，存在边界误差（白皮书 §3.3）。
3. 极端值被隔离不被删除（保留原值可查），确保总体口径不被个别不完整样本污染（白皮书 §8）。

> 一句话定调：**数据完整度是大多数异常的根因，不是算法错误**。系统已通过资格判定与异常隔离把不可信样本挡在统计之外，留在台面上的是可信样本。

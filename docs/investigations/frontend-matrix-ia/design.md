# 前端翻版设计：主体 × 维度矩阵 IA

> 定稿 2026-06-17。整个前端从"按业务域平铺"翻版为「主体(选谁) × 维度(看什么)」矩阵，接入客观平台数据。实现契约见 `.trellis/tasks/06-17-frontend-matrix-ia/prd.md`。

## 核心心智
- **主体轴**：组织/个人/项目/仓库(4 下钻) + 总览 + 需求。
- **维度轴**：使用/质量/效率/成本/贡献(5 维)。
- **时间线**：全局第三维(顶部统一时间范围 + 每视图趋势打头)。
- **导航 = A 主体优先**：一级选"谁"，进下钻后页内维度 Tab 选"看什么"。

## 4 项口径决策(用户拍板)
1. **成本**=两套并列卡(平台 AI花费 ‖ 看板人天)，口径标清不混。
2. **质量**=出「AI服务健康度」初版(成功率/错误率/时延)，明确非代码质量；项目/仓库该维=建设中。
3. **效率**=看板提效比为主 + 平台「AI响应性能」附属小卡。
4. **项目/仓库**平台填不了→维持看板派生口径，平台数据只进 总览/个人/组织。

## 平台数据关键约束
- chat-stats=外部服务，看板只代理，**不能加参数**；源库无项目/仓库/部门字段。
- 能强填 总览/个人/组织；填不了 项目/仓库。
- 组织聚合走 universal_id→看板 user_id(同源)→部门，看板侧聚合。
- 个人/组织时间线用 `/stats/users/ranking` 按周切窗；全局日趋势白捡。
- **降级护栏**：`chat_stats_enabled=false` 时平台格回退看板派生/占位，不空页。

## 分期
- **Phase 1**(本任务)：纯前端 IA + 复用现有平台端点。导航壳/全局时间/4下钻重组/平台接入(总览·个人·组织)/成本双卡/质量健康度/效率性能附属/router 重定向/降级护栏。
- **Phase 2**：项目/仓库经 task_id 反查平台；后端 per-entity 时间桶(若需)。
- **Phase 3**：真代码质量维度数据；补个人人天成本等缺口。
